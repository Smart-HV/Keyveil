Send a password once. Then it's gone.

KeyVeil encrypts secrets in your browser and turns them into a link that works once. The server stores ciphertext only – it never sees the key, the text or the password.

Anatomy of a KeyVeil link

How it works

  1. Encrypt in your browser

    Paste a password or a note, pick an expiry and how often it may be opened. AES-256-GCM encryption happens on your device, optionally with an extra password hardened by Argon2id.

  2. Share the link

    Send it through any channel. Link previews and crawlers only load the page; nothing is consumed until a person clicks to reveal it.

  3. Open once, then it's gone

    The recipient's browser decrypts locally. The last allowed view deletes the ciphertext from the database before the response is even sent.

What the server knows

Stored until expiry or the last view

  • The encrypted envelope: ciphertext, IV and salts
  • Expiry time and view limit
  • How often the secret has been opened
  • A hash of a hash of the delete token

Never

  • The text you share
  • The decryption key
  • Your additional password
  • Your IP address, browser or referrer in the database

Built to be checked, not trusted

Security claims are only as good as the tests behind them. Every one of these runs in CI.

Standard cryptography
AES-256-GCM, HKDF-SHA-256 and Argon2id through WebCrypto and a single WASM library. Nothing home-made.
Two implementations agree
Test vectors are generated with OpenSSL and libsodium and reproduced byte for byte by the browser code.
Atomic claims
Parallel requests race against a PostgreSQL row lock. Tests fork real processes and prove that exactly the allowed number of views succeed.
The key stays put
An end-to-end test in Chromium, Firefox and WebKit asserts the key never appears in any request URL, body or header.
Strict Content Security Policy
No inline scripts or styles, no third-party requests, no analytics, no service worker. Just like this page.
Nothing to probe
Unknown, expired, used and deleted secrets return the same response, and every endpoint is rate limited.

Not audited yet. KeyVeil has not had an independent security audit. Like every web app that encrypts in the browser, it also depends on the server delivering honest JavaScript, so run it from a release you have reviewed.

Self-host it

A standard Laravel app. You need PHP 8.3+, PostgreSQL, Redis in production and HTTPS. No external services, no accounts. 

git clone https://github.com/Smart-HV/Keyveil.git keyveil
cd keyveil
cp .env.example .env
composer setup
composer run dev
Run it in production Reverse proxy, scheduler, backups and a release checklist. Make it yours Name and logo via .env, colors and fonts in one CSS file. Read the protocol Byte lengths, encodings, key derivation and test vectors.

The interface is currently available in German. Translations are welcome.
